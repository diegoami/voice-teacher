2. Specify lesson start/continue, feedback, finish/move-on, current and legacy

3. Present the proposal for owner review. Keep actual navigation implementation,
   applicable browser recovery/focus checks and real-phone acceptance explicitly

4. Check proposal links and the standalone synthetic wireframe on desktop and
   phone-sized screens, keyboard navigation, back/refresh, labels/focus and
   overflow. These checks validate only the proposal artifact.

compare the issue77/78 contracts and current UI. Validate local links and HTML,

## Hazards

A clickable wireframe is not the working app. Never use it to imply that auth,
recording recovery, history import or proposed navigation already works. No
personal data or server credentials are included, and it makes no network calls.
