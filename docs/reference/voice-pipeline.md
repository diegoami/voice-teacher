# Durable speech pipeline

T10 adds configurable ElevenLabs adapters, `VoicePipeline`, owner-bound teacher
audio and a runnable personal-server composition. It preserves the POC's Scribe
v2 / Multilingual v2 defaults and authored stress, while using the durable T06
coordinator. Importing the core does not construct a provider or load credentials.

```bash
uv sync --locked
uv run python -m voice_teacher --data-dir /private/server-data \
  --judge-model YOUR_EXPLICIT_OPENROUTER_MODEL --origin http://localhost:8000
```

Supply `VOICE_TEACHER_OPERATOR_TOKEN`, `ELEVENLABS_API_KEY` and
`OPENROUTER_API_KEY` through private environment/configuration. The executable does
not search or copy `.env` files. Judge model selection is explicit, through the
argument or `TEACHER_MODEL`; there is no model fallback. The OpenRouter adapter
ports the measured uk/en judge policy and strict verdict schema, with numeric
usage only, bounded output/timeouts and no automatic rate-limit sleep/retries.
The local API serves through Uvicorn on loopback by default, with proxy-header
trust and access logging disabled. `--assets` can serve T15's built same-origin
client. Configure phone HTTPS under T28. No progress remote is selected or worker
started implicitly; configure T12 separately after ownership/privacy verification.

For custom rendering, construct `SpeechConfig` and call `build_app(...,
speech_config=config)` or instantiate the adapters/pipeline directly. Explicit
settings include model IDs, voice, MP3 output format, seed, voice settings and
pronunciation version. Default settings are stability 0.5, similarity boost 0.75,
style 0, speaker boost true and speed 1. These are sent per request rather than
depending on mutable account settings. Supported output formats are
`mp3_44100_128` (default/measured) and `mp3_22050_32` (explicit alternate).

The adapter follows the official [transcription](https://elevenlabs.io/docs/api-reference/speech-to-text/convert)
and [synthesis](https://elevenlabs.io/docs/api-reference/text-to-speech/convert)
interfaces. Recognition sends the pinned session language, disables diarization,
audio-event tagging and transcript cleanup, and supplies no expected-target bias.
It returns only text and optional reported duration. Language probabilities or
word log probabilities are not turned into confidence scores or pronunciation
claims. Multilingual synthesis retains mixed English instructions/Ukrainian
models without forcing all teacher speech into the learner's language.

## Durable stages and recovery

1. An audio request binds learner/session/request ID to the recording's SHA-256,
   media type, pinned language and expected revision in private SQLite v6. Raw
   learner audio is not persisted by this pipeline. Reusing an ID for different
   bytes/revision/type is a conflict before another provider call.
2. Recognition happens outside database transactions. A successful transcript is
   cached durably before judging. Failed/empty recognition stores a separate
   status and leaves native engine state/evidence unchanged. Retrying an identical
   transient failure is allowed; uncertain remote response/cache boundaries can
   repeat a provider charge, never silently promise exactly-once billing.
3. Coordinator owns judging and the atomic evidence/session transition. Cached
   recognition and judged results survive restart. Synthesis runs after that
   transition, using saved teacher plans. Retrying failed delivery reuses the
   original transition; it does not recognize, judge or record evidence again.
4. Creation saves its first teacher plan before synthesis too. If initial audio
   preparation fails, the client already knows its chosen session ID and recovers
   through authenticated `GET /api/v1/sessions/{id}`, without recreating a session.
   Text turns, controls and status use the same contextual delivery boundary.

`Coordinator` still accepts the old `delivery(says)` callback; production speech
uses `delivery_context(learner,session,request,says)` so concurrent learners never
share mutable delivery context. Per-session/per-cache-key locks coordinate one
writer process, with SQL revision/idempotency guards. Multiple active writer
servers remain unsupported. Provider timeouts default to 30 seconds; T27 owns
broader admission/cancellation/latency budgets.

Teacher audio lives in private `teacher-audio/` under the server data directory,
outside code/content/progress Git trees. Cache identity hashes marked text,
language, model/voice/settings, pronunciation version, seed and output format.
The seed is a best-effort provider setting; deterministic request identity does
not promise identical regenerated bytes. File publication is atomic and fsynced;
SQLite stores size/hash before an owner/session/plan attachment is usable. Files
are 0600 and symlinks are refused. Corrupt/missing files regenerate from their
saved text/config without changing progress. An old voice's missing file needs
the corresponding configuration or a refreshed current presentation.

Cache bytes can be shared, but knowing a content ID is insufficient for access.
Every download checks a recorded attachment for the authenticated learner/session.
The API additionally checks ownership and current session revision. Provider
responses, errors and filesystem paths are not exposed. Teacher display text uses
plain rendering; synthesis receives the authored stress-marked text unchanged.
T26 owns retention/deletion policy; cached audio and in-flight provider metadata
are never copied by T11/T12 progress export.

## Learner-reported recognition problems

Authenticated owners can read
`GET /api/v1/sessions/{session}/recognition/{request}` and submit `{}` to
`POST /api/v1/sessions/{session}/recognition/{request}/report`. The report is an
explicit learner annotation, not a confidence estimate or confirmed correction.
It appends one private saved-state checkpoint containing the report and supporting
accepted-turn ID when one exists. Original evidence, assistance and native lesson
state remain unchanged. Repeated reporting is idempotent. The response includes
the new revision, so the next request uses that version.

Reporting an uncommitted recognized request cancels that request's pending judge
intent; use a fresh request ID for a new recording. An unrelated unfinished turn
must finish before an older recording is annotated. This avoids both stale work
and accidental cancellation of a different turn. A failed checkpoint retries
without duplicating its annotation. The private snapshot is authoritative; a local
recognition-row flag is a retryable projection.

Reports survive subsequent turns, export/import and server handoff even though
audio caches/request receipts do not. Coordinator capsule v2 preserves these
annotations; v1 capsules remain readable and upgrade on a new transition. Older
coordinators reject v2 instead of silently dropping the reports. Evidence queries
must show the report separately from original outcomes, without recasting an ASR
problem as a confirmed learner mistake or inventing mastery.

## Bounded live smoke

After explicitly selecting credentials, run from a source checkout:

```bash
uv run python tools/voice/smoke.py --artifacts /private/new-speech-smoke
```

It uses one short synthetic authored phrase, one synthesis request and one
language-locked recognition request (30-second per-call timeout, 256 KiB output
cap). It does not call a judge or upload learner recordings. A fresh private
artifact directory prevents accidental overwrites; credentials are read from the
selected environment and never recorded. The report contains actual configuration,
synthetic phrase/transcript, durations and hashes. Audio/report stay outside Git.

2026-10-16 live result, verified by the main session with user-selected existing
ElevenLabs credential: Scribe `scribe_v2`, language `uk`; synthesis
`eleven_multilingual_v2`, voice `JBFqnCBsd6RMkjVDRZzb`, `mp3_44100_128`, seed 1 and
the explicit default settings above. Phrase `Оди́н квито́к, будь ла́ска.` was recognized
as `Один квиток, будь ласка.`. Synthesis took **2.433 s**, recognition **0.707 s**;
the provider reported **1.579 s** audio, 26,374 bytes. Synthetic audio SHA-256:
`1ebf59c67e5595778e0a99dee431f898460bdca3b54c76bc9995e54be19c14ea`.
Initial account-settings probes were denied for missing read permission; the
final speech-only check used explicit settings with the same credential.
These are API timings for a synthetic transport check, not phone playback latency,
independent pronunciation validation or real learner acceptance. T19/T27 own those.

Offline verification:

```bash
uv run pytest tests/providers tests/integration/test_voice_pipeline.py -q

```

Coverage includes transport sanitization/timeouts, complete cache inputs, authored

process recovery, partial/corrupt cache recovery, initial reply/status recovery,
owner-bound audio, portable recognition reports and checkpoint retry, v1 capsule
compatibility and transactional v5-to-v6 migration success/failure.
