## Scope

Let the learner pause an activity, leave the app and resume later, including after a server restart. Show pending-response recovery and completed versus interrupted activities. Handle switching sources by retaining separate saved sessions.

## Done when

1. A browser refresh and new client connection resume the same activity, step, assistance and pinned content after the server restarts.
2. Pausing during upload/judging/synthesis and resuming yields one accepted attempt and an intelligible pending or ready response.
3. Source/profile changes cannot splice activity state or progress between sessions; finished sessions cannot accept another learner turn.

## Verification

Planned checks, not commands claimed to exist or pass today. Resolve paths and


The PR records one result per numbered criterion, relevant baseline/regression

## Hazards

Client localStorage cannot be the authority for session state. Do not mark a paused session completed just to save it.
