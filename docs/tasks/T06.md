## Scope

Introduce durable request IDs, expected session revisions and resumable work stages. Persist accepted input, decisions and planned teacher replies before delivery. Serialize processing within each session and enforce state checks within the transaction. Reuse results when the client loses a response.

## Done when

1. Repeating a request ID or submitting concurrent turns records one accepted attempt/evidence transition; stale revisions and mismatched ownership are rejected.
2. Failure injection before/after judging and commit, plus restart after response loss, resumes from the saved stage without a second progress transition.
3. A synthesis or playback-delivery failure retries the saved teacher response without consuming another learner attempt; stop/pause races leave a valid persisted state.
