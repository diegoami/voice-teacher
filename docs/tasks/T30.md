## Scope

Validate the requested product as one local deployment: selectable lesson repositories, all three modes, private durable progress and recovery. Consolidate mode evaluations and measured phone experience. Package a reproducible release with versioned schemas and upgrade/rollback guidance. This task integrates existing features rather than adding unrelated product scope.

## Done when

1. End-to-end evidence covers selecting two repositories, each supported mode, an interrupted/resumed session, delayed Git sync and a restored instance without source writes or missing/duplicate progress.
2. The full relevant offline/browser suite and mode evaluations pass; required real-device checks have named evidence and every release-blocking finding is resolved.
3. A versioned release candidate documents install/update/rollback, provider configuration, measured latency/usage and remaining limitations. Owner acceptance is recorded before publishing a release or tag.

## Verification

Planned checks, not commands claimed to exist or pass today. Resolve paths and
required manual participation at main-session preflight before dispatch.

```text
uv run pytest tests -q
npm --prefix apps/web run build
npm --prefix apps/web run test:e2e
Manual: execute docs/acceptance/local-release on the real phone and restored instance.
```

The PR records one result per numbered criterion, relevant baseline/regression
checks and any manual evidence. Independent exact-head review precedes merge.

## Hazards

Do not call the three-mode release complete after only repetition and guided practice; do not fabricate owner acceptance or silently waive phone checks.
