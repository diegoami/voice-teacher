## Scope

Establish minimal root Python test configuration so contract checks can run before engine extraction. Specify source, course, lesson, step and item identities; display/speech text; available modes; guided/recall goals; private session snapshots and append-only progress events. Separate learner profile and assistance evidence from reusable content. Define revision and event ordering rules and language/instruction-language fields. Use synthetic fixtures only.

## Done when

1. Valid repetition-only, guided and topic packages validate; unknown schema versions, invalid references and duplicate IDs within a namespace fail with useful locations.
2. Identical local IDs from two source namespaces remain distinct; a learner profile or progress payload in a reusable curriculum package is rejected.
3. Progress fixtures preserve source revision, mode, turn reference, assistance and original/later practice provenance through serialization; missing mandatory references fail.

## Verification

Planned checks, not commands claimed to exist or pass today. Resolve paths and
required manual participation at main-session preflight before dispatch.

```text
uv run pytest tests/contracts -q
```

The PR records one result per numbered criterion, relevant baseline/regression
checks and any manual evidence. Independent exact-head review precedes merge.

## Hazards

Do not use folder names or phrase text as global identities. Preserve known stress marks and avoid treating coverage as mastery.
