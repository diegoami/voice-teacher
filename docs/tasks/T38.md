# T38 Make development and release review cloud-compatible

- **Kind:** infrastructure/process
- **Issue:** [#83](https://github.com/diegoami/voice-teacher/issues/83)
- **Owner direction:** 2026-10-23; follow recent malpaco and goal2 cloud changes.
- **Branch:** `task/T38-cloud-workflow` locally, assigned session branch in cloud.
- **Implementer:** current main Codex session, OpenAI family.
- **Review:** optional per PR; reports belong to the integrated release review.
- **Owns:** instruction/process/setup/artifact docs and tools, development CI.

## Scope

Use one checkout without new worktrees, remove the mandatory external-review
and family gate, retain release reviews and exact-head evidence. Prepare locked
Python/web development with no machine-only dependencies. Store required private
files in private Drive; keep credentials in environment secrets. Specify Claude
account-side environment, networking and verification accurately.

## Done when

1. Instructions, active contracts and PR template consistently use branch-based
   work and optional PR review. Historical evidence is preserved and identified.
2. Fresh-directory setup, backend checks, web build/unit and browser smoke run
   without private files, paid providers, sibling checkouts or reviewer tools.
   CI checks backend and cloud tooling as well as the web suite.
3. A private Drive folder is verified; available local-only POC samples are
   archived with checksums, and portable private-file transfer is documented.
4. Claude setup/network/variable settings are concrete and ready to apply;
   account-side creation and an actual Claude cloud run are reported separately
   if no authenticated settings surface is available in this session.

This does not merge other PRs, publish a release, remove old worktrees, migrate
canonical learner history, implement T29 runtime backups or pass phone gates.

## Owner cloud-start observation

The first account-side setup attempt failed with exit 127 because the early
environment script could not find `tools/cloud_setup.sh`. The environment
setup field must stay empty (or `true`); repository dependency setup belongs to
the committed SessionStart hook after checkout. A fresh actual Claude run is
still needed to verify that hook and the complete environment.
