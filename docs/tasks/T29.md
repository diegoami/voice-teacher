## Scope

Create consistent database backups plus required configuration references and optionally retained private audio. Restore into a clean data directory and reconcile exported and not-yet-exported progress. Use SQLite backup facilities rather than copying a changing database file. Protect backup contents and document retention.

## Done when

1. An active WAL-mode database snapshot restores valid session/event state, including pending outbox work, without relying on a lucky checkpoint.
2. A clean restored instance resumes an interrupted session and exports pending events once; previously pushed events remain deduplicated.
3. Corrupt/incompatible backups are rejected without overwriting the current store; the documented restore drill records what is and is not covered, including optional audio.

## Hazards

Git export does not protect unexported local work or retained audio. Restores must never overwrite the live store implicitly.
