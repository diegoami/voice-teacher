## Scope

Provide a repeatable local launch for the app/API, persistent data directories and a stable HTTPS phone endpoint. Choose private-network HTTPS or a named tunnel with the operator at preflight. Document first-run pairing, server availability, updates and shutdown. Support the selected Linux host and clearly state other host requirements.

## Done when

1. A clean configured launch serves app/API health and preserves data across restart; credentials and runtime data remain outside the code/content checkouts.
2. The real phone reaches the stable HTTPS origin and can grant microphone permission; restarting the service does not change its installed app URL.
3. The runbook covers automatic start/restart, readiness, migration failure and endpoint access control, and accurately states that external speech/model services still require internet.

required manual participation at main-session preflight before dispatch.

Manual: launch from a clean operator configuration, inspect HTTPS/health, pair the real Android phone, restart and verify the same address and persisted session.

The PR records one result per numbered criterion, relevant baseline/regression

## Hazards

Plain HTTP to the PC LAN address does not gain the localhost microphone exception. Never expose a token-path POC as the production access scheme.
